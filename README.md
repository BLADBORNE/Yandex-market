# Yandex Market

Учебное реактивное веб-приложение «Витрина интернет-магазина». Пользователь может
просматривать, искать и сортировать товары, управлять корзиной, оформлять заказы и
просматривать историю покупок.

## Стек

- Java 21;
- Spring Boot 3, Spring WebFlux и Reactor Netty;
- Spring Data R2DBC и PostgreSQL (`r2dbc-postgresql`);
- Thymeleaf;
- Gradle;
- JUnit 5, Reactor Test (`StepVerifier`), WebTestClient и Testcontainers.

В приложении нет Spring MVC, Servlet API, Spring Data JPA, Hibernate и блокирующего
JDBC-доступа к данным. Все репозитории и сервисы возвращают `Mono`/`Flux`, а
изменение корзины и оформление заказа выполняются в реактивных транзакциях.

## Требования

- JDK 21;
- Docker с запущенным Docker Engine — для PostgreSQL и интеграционных тестов.

Использовать установленный локально Gradle не требуется: проект содержит Gradle
Wrapper.

## Тесты и сборка

Запустить все модульные, web-slice и интеграционные тесты:

```bash
./gradlew clean test
```

Выполнить полную проверку и собрать executable JAR:

```bash
./gradlew clean build
```

Интеграционные тесты автоматически запускают PostgreSQL 17 через Testcontainers.
Они используют один переиспользуемый Spring-контекст без `@DirtiesContext`;
изменяемые таблицы очищаются между сценариями реактивным SQL.

После сборки создаётся один исполняемый файл:

```text
build/libs/market-app.jar
```

## Локальный запуск

Запустить PostgreSQL:

```bash
docker compose -f docker-compose.dev.yaml up -d
```

Запустить приложение из исходников:

```bash
./gradlew bootRun
```

Или запустить собранный executable JAR:

```bash
java -jar build/libs/market-app.jar
```

Приложение будет доступно по адресу
[http://localhost:8080/items](http://localhost:8080/items). Корневой путь
`http://localhost:8080/` ведёт на ту же витрину.

Для остановки PostgreSQL:

```bash
docker compose -f docker-compose.dev.yaml down
```

## Запуск приложения через Docker Compose

Сначала собрать JAR, затем запустить приложение вместе с PostgreSQL:

```bash
./gradlew clean build
docker compose up --build
```

`market-service` запускается только после успешной проверки готовности базы.

Остановить контейнеры:

```bash
docker compose down
```

Добавьте флаг `-v`, только если нужно удалить локальный том вместе с данными:

```bash
docker compose down -v
```

## Конфигурация

Настройки по умолчанию находятся в
`src/main/resources/application.yaml`.

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `HOST` | `localhost` | адрес PostgreSQL |
| `PORT` | `5432` | порт PostgreSQL |
| `POSTGRES_DB` | `market_db` | имя базы |
| `POSTGRES_USER` | `dev` | пользователь |
| `POSTGRES_PASSWORD` | `qwerty` | пароль |

Схема и исходный каталог товаров инициализируются через реактивное подключение из
`src/main/resources/db/schema.sql` и `src/main/resources/db/data.sql`. Скрипты
идемпотентны и подходят как для новой базы, так и для повторного запуска.

## Основные маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/` или `/items` | витрина, поиск, сортировка и пагинация |
| `POST` | `/items` | изменить количество товара из витрины |
| `GET` | `/items/{id}` | карточка товара |
| `POST` | `/items/{id}` | изменить количество из карточки |
| `GET` | `/cart/items` | корзина и итоговая стоимость |
| `POST` | `/cart/items` | увеличить, уменьшить или удалить товар |
| `POST` | `/buy` | оформить активную корзину |
| `GET` | `/orders` | история заказов |
| `GET` | `/orders/{id}` | страница заказа |

Параметр `action` принимает `PLUS`, `MINUS` или `DELETE`; `DELETE` разрешён только
на странице корзины. Витрина поддерживает сортировки `NO`, `ALPHA`, `PRICE` и
размеры страницы от 1 до 100 (в интерфейсе: 2, 5, 10, 20, 50 и 100).

## Гарантии целостности

- в базе может существовать только одна активная корзина;
- параллельные добавления товара выполняются атомарно и не теряют количество;
- количество товара в корзине всегда положительное;
- одна корзина может быть оформлена только один раз;
- название, цена и количество позиций заказа сохраняются как неизменяемый снимок;
- оформление блокирует выбранную корзину, создаёт заказ и закрывает её в одной
  реактивной транзакции.
